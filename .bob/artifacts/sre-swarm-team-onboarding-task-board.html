Five Architecture Pillars

Durable Execution
Temporal.io

Fault-oblivious orchestration loop. Crashes mid-incident and replays from event history without losing state.

Agent Tool Calling
MCP · stateless 2026-07-28

Every request is a self-describing POST. No session handshake. Auth via header on every call.

Long-running Actions
MCP Tasks extension

Async task handles with explicit state: working → input_required → completed.

Ground-truth Telemetry
eBPF mock + OpenTelemetry

Zero-instrumentation kernel trace simulation. ~2.4% CPU overhead. Structured as OTLP spans.

Dynamic Rollbacks
Saga Orchestration

Compensating transactions fanned out in parallel. Idempotent. No two-phase commit.

The Golden Rule — Workflows vs Activities

Workflows must be 100% deterministic. All I/O lives in Activities.

✅ Allowed inside a Workflow ❌ Never inside a Workflow
workflow.execute_activity(...) httpx.get(...) or any network call
workflow.wait_condition(...) LLM API calls
workflow.now() datetime.now() or time.time()
asyncio.gather() over activity futures random.random() or any non-deterministic value
Pure data transformation File I/O, environment reads, subprocess calls

If you are unsure — put it in an Activity. Temporal retries Activities safely. It cannot safely retry I/O inside a Workflow.

Gotchas & Known Traps

⚠ datetime.now() inside a Workflow breaks replay

Temporal's replay engine must reproduce the exact same value it recorded. Use workflow.now() instead. datetime.now() will differ on replay and cause a non-determinism error.

⚠ Modules that do I/O at import time will crash the Workflow sandbox

Wrap all Activity imports inside with workflow.unsafe.imports_passed_through():. This is already done in incident_response.py — follow that exact pattern for any new Activity you add.

⚠ Activity retries are independent — the Workflow does not fail on activity failure

If call_mcp_tool fails 3 times, the workflow pauses and waits. It does not propagate a workflow failure. Design Activities to be idempotent and retry-safe.

⚠ 409 from a compensation endpoint means "already done" — treat it as success

The Saga fan-out may replay if the worker crashes mid-execution. Your /cancelOrder and /refundPayment endpoints must return 409 for duplicate calls. The execute_compensating_transaction Activity already handles 409 as a success — don't change that behaviour.

⚠ The MCP server must be completely stateless

Do not store session context between requests. Every POST /mcp must be fully self-describing. Auth context is delivered by the Authorization header on every single request — not established once at connection time.
